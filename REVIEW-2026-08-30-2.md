## 1. Критичные

### 1.1 [H] `git ls-remote --upload-pack=<cmd>` выполняет произвольную команду без промпта

`internal/agent/tools/safe.go:55` + `bash.go:245-262`. `git ls-remote`
в `safeCommands`; `--upload-pack='touch ../pwned; git-upload-pack' .` не
содержит метасимволов цепочки, `isSafeReadOnly=true`, команда выполняется
с нулём запросов разрешения (воспроизведено). Фикс: убрать `git
ls-remote` из safe-списка (это ещё и сетевая операция) либо gate по
`--upload-pack`/`-u`.

### 1.2 [H] `git grep -O<pager>` запускает программу на каждом найденном файле без промпта

`safe.go:52`, плюс `confinement.go:144` пропускает confinement-проверку,
т.к. `grep` в `readOnlyGitSubcommands`. `git grep -Orm hello` → `rm
<файлы>` (воспроизведено с `-O'touch ../pwned2 --'`). Фикс: добавить
`git grep` в `argumentGatedSafeCommands` с отказом на
`-O`/`--open-files-in-pager`.

### 1.3 [H] `agentsLoadedMsg` не адресован main-экрану — секция agents замерзает навсегда после одного ctrl+e

`internal/ui/model/root.go:308-376` vs `agents_cache.go:54-61`.
Сообщение не несёт `uimsg.MainScreenOwned`/`uiOwned`, роутится по
активному экрану. Делегация идёт (панель опрашивает `ListTasks` каждые
3 с), пользователь жмёт ctrl+e в момент fetch → результат попадает в
`handleDashboardMsg`, который всё кроме мыши бросает →
`cache.InFlight` остаётся true, `listcache.DispatchRefresh` навсегда
возвращает nil. Тот же класс бага, что описан в комментарии
`root.go:765` как исправленный для других кэшей. Фикс: embed
`uimsg.MainScreenOwned` + добавить в `var _` proof-блок.

### 1.4 [H] Результаты send/shell теряются на dashboard — промпты молча уходят в очередь навсегда

`root.go:364-376`; `shell.go:17-26,77-96`; `send.go:56-63,124`;
`update_session.go:38-56,311-324`. `shellResultMsg`,
`agentRunSubmittedMsg`, `sendMessageErrorMsg`, `createSessionMsg`,
`bangSessionCreatedMsg`, `cancelTimerExpiredMsg` без владельца.
Сценарий: `!go test ./...`, ctrl+e (биндинг Threads не gated на busy —
`keypress.go:181`), вернуться. `shellResultMsg` выброшен: ShellItem
крутится вечно, `bangCancel` держит `isAgentBusy()`, `pendingSendActive`
true → каждый `sendMessage` в `pendingSendQueue`, никто не дренирует до
загрузки *другой* сессии. Фикс: помечать `uiOwned{owner: m}` при
диспатче, как `busyStateMsg`.

### 1.5 [H] Completion, пришедший во время summarize, не будит припаркованную делегацию

`internal/agent/usage.go:123-146` (defer summarize) +
`completion_inbox.go:283-289` (`wakeEligibleLocked` требует
`s.active == nil`) + `idle_summarize.go:336-339` vs
`turn_dispatcher.go:180-181`. summarize занимает active-слот, а его
defer делает только `clearActiveIfMatch` + `drainNext`, без
`wakeFromInboxIfIdle` (он есть лишь в defer `runTurn`,
`run_turn.go:641`). `DeliverTaskCompletion` в этот момент →
`wakeEligible=false`, ничего не перепроверяет инбокс. Триггер
рутинный: комментарий `markActivity` утверждает, что delegation-сессии
не попадают в idle sweep, но `runContinuation` и `RunAccepted→run`
помечают все task/thread сессии — припаркованный task (ждёт детей,
обычно >60k токенов) именно то, что 4-минутный sweep выбирает. Ребёнок
завершился во время 20–60 с summary → родитель в StatusRunning до
watchdog. Фикс: в defer summarize после `clearActiveIfMatch` звать
`a.wakeFromInboxIfIdle(context.WithoutCancel(ctx), sessionID)` (и на
раннем `claim != nil` return); плюс либо пропускать
`isDelegationSession` в `sweepIdleSessions`, либо поправить комментарий.

### 1.6 [H] vercel: index out of range в non-stream reasoning parser

`third_party/fantasy/providers/vercel/language_model_hooks.go:124-128,140`
и `:149-157,166`. Тот же баг, что 3.32 прошлого аудита, но фикс
(8f95ad607) лёг только в openrouter. `Generate` через Vercel с
`openai/*` или `google/*` reasoning-моделью, где
`reasoning_details[0].index != 0` или есть пропуск → паника. Фикс:
скопировать grow-to-`Index+1` из
`openrouter/language_model_hooks.go:116-125` в обе ветки.

## 2. Средние

### agent / thread

- **2.1** `internal/agent/run_turn.go:835-837` — отменённый ход
  бросает всё, что встало в очередь после Cancel. `dispatcher.cancel`
  чистит очередь только на момент вызова; пока Stream не вернулся
  (медленный tool: bash/MCP/LSP), `s.active` ещё занят, новый промпт
  встаёт в очередь с `acceptSeq > mark`, а cancel-путь не зовёт
  `drainNext`. RunID-промпт (`thread_send`, `sennit run`) блокирует
  вызывающего до таймаута. Та же дыра при отмене через ctx вызывающего
  и при `t.currentAssistant == nil` из-за ошибки `messages.Create` на
  шаге 0. Фикс: прогонять хвост `completeTurn` и на cancel-пути.
- **2.2** `internal/agent/delegation_finalizer.go:730-742,824-843` +
  `turn.go:565-570` + `runtime_builder.go:663-673` — саб-агент со своей
  `model:` после успешного 401-refresh продолжает со старыми
  credentials: `OnAuthRefresh` кладёт в `active` **coder**-runtime,
  `modelProvider` принимает его только при совпадении provider+model, а
  `t.model` построен со статическим ключом → повторный 401, делегация
  падает. Триггер: любая длинная делегация на Copilot/Codex/Anthropic
  OAuth через истечение токена. Фикс: строить refreshed model для
  `config.Agent` саб-агента (`buildCustomAgentModel`).

### workspace / config
