Целевой поиск багов по всему дереву (`internal/**`, `third_party/**`,
~174k строк non-test Go). В отличие от ревью 2026-08-28, здесь только
дефекты с конкретным сценарием отказа — без SOLID/DRY и планов

Метод: `go vet ./...` и `golangci-lint run ./...` — чисто, то есть всё

(agent+tools, ui, config/cmd/oauth, db/shell/lsp/fsext, third_party,

Легенда: **[H]** — ломает реальный сценарий или роняет процесс,
**[M]** — неправильное поведение с обходным путём, **[L]** — краевой
случай или расхождение с комментарием/тестом.

## 1. Критичные

### 1.1 [H] `.sennit/sennit.json` мержится дважды — все массивы удваиваются

`internal/config/paths.go:46-53` (`lookupConfigs` включает
`.sennit/sennit.json` в список проектных слоёв) +
`internal/config/build.go:89-108` + `internal/config/load.go:132-168`
(`applyWorkspaceConfig` перечитывает `<DataDirectory>/sennit.json`, что по
умолчанию тот же файл).

`go-jsons.Merge` конкатенирует слайсы. Репро (overlay-тест на
`buildConfig` с trusted-каталогом): `mcp.x.args=["a","b"]` →
`[a b a b]`, файл дважды в `loadedPaths`. Следствия: хук из
`hooks.PreToolUse` запускается дважды на каждый tool call, MCP/LSP
получают `[-y pkg -y pkg]`, `[serve serve]`. Дедуп есть только у
`context_paths`/`disabled_tools`/`allowed_tools`/`skills_paths`. Global-only
Problem для этого файла тоже пишется дважды.

Фикс: в `applyWorkspaceConfig` выходить, если `filepath.Clean(workspacePath)`
уже есть в `*loadedPaths` (либо исключать его из `configPaths` до
`loadFromConfigPaths`). Регрессионный тест: `len(hooks.PreToolUse)==1`.

### 1.2 [H] Ротация аккаунтов работает только один раз, потом — горячий цикл

`internal/agent/runtime_builder.go:741-790, 827-865`
(`makeRateLimitCallback`, `makeThresholdRotateCallback`), строятся один раз
на ход в `turn_dispatcher.go:231-232` и замыкают `providerCfg` по значению.
`applyRotationPick` (`:710`) активирует новый аккаунт и кладёт новый runtime
в `active`, но `providerCfg.Account` в замыкании не обновляется.

Сценарий (A→B): 429 на A → `MarkRateLimited(A)`, выбран B. Следующий 429
уже на B → снова `MarkRateLimited(A)` (B не помечен), `Pick(current=A)`
возвращает B, `picked.ID != A` → `applyRotationPick(B)` повторно (rebuild +
уведомление «switched»), возвращает nil → fantasy ретраит сразу на всё ещё
залимиченном B → цикл до исчерпания бюджета ретраев. Threshold-вариант:
после A→B каждый шаг читает `UsageFor(A)`, `ShouldRotate` вечно true,
rebuild + уведомление на каждом шаге.

Фикс: брать текущий аккаунт внутри коллбэка из
`active.load().providerCfg.Account` для `MarkRateLimited`/`Pick`/`UsageFor`
и no-op сравнения.

### 1.3 [H] Локальный патч fantasy отключил `schema.Normalize`

`third_party/fantasy/agent.go:1121-1129`. Патч добавил `InputSchema` в
`ToolInfo`, и `prepareTools` теперь зовёт `schema.Normalize` только на
fallback-пути. `funcToolWrapper.Info()` (`tool.go:184`) всегда заполняет
`InputSchema`, а MCP-инструменты (`internal/agent/tools/mcp-tools.go:115`)
прокидывают схему сервера как есть — `Normalize` не выполняется никогда.
Он превращал `"type": ["string","null"]` в `anyOf` и добавлял
`"items": {}` к голому `"type":"array"`; OpenAI такое отвергает («array
schema missing items»), а `toOpenAiTools`/`toResponsesTools` не
нормализуют.

Сценарий: любой MCP-сервер со свойством `type: array` без `items` → 400 на
каждый запрос к OpenAI/Codex, где есть этот инструмент. До патча работало.

Фикс: звать `schema.Normalize(inputSchema)` безусловно после
clone/fallback (идемпотентен, рекурсивен по `$defs`/`anyOf`).

### 1.4 [H] `provider remove X` + `provider add X` в `.sennitrc` ломает загрузку всего конфига

`internal/shellconfig/provider.go:49` (`providerAdd` →
`childMap(b.section("providers"), id)`),
`internal/shellconfig/model.go:87-96` (`modelAdd` считает tombstone
существующим провайдером).

`providerRemove` → `removeLocal` (`builder.go:98`) заменяет
`providers[id]` на `{__sennit_tombstone: …}`. Это `map[string]any`, так что
`childMap` возвращает её и `applyFlags` пишет `api_key`, `name` рядом с
маркером. `lsp add`/`mcp add` идут через `ConfigBuilder.addLocal`
(`builder.go:62-95`), чей комментарий описывает ровно этот случай;
`provider add`/`model add` туда не заведены.

Результат: `{"openai":{"__sennit_tombstone":{…},"api_key":"k"}}` →
`ParseTombstone` (`builder.go:35`): «tombstone for providers.openai must
not contain other fields» → загрузка конфига падает целиком. То же для
`provider remove openai` + `model add openai/gpt-x`.

Фикс: `p := b.addLocal(b.section("providers"), "providers", id)`; в
`modelAdd` резолвить провайдера через `addLocal` (или через
`ParseTombstone` → `Replacement`).

## 6. Статус (закрыто 2026-08-30)

Все критичные (раздел 1), все средние (раздел 2) и 37 из 38 низких
закрыты. Каждый фикс сопровождается регрессионным тестом, проверенным на
падение против кода до правки.

Не исправлено сознательно — **3.17**, adoption токена Codex с диска при
пустом `accountID`. Это не недосмотр: `TokenFromDiskFor` документирует
поведение («не с чем сверять — берём как есть»), и
`TestTokenFromDiskForChecksAccount` закрепляет его отдельным кейсом с
тем же обоснованием. Менять это — продуктовое решение о том, что
делать, когда учётная запись не опознаётся, а не устранение дефекта.

Что стоит знать про остальные пять, закрытых последним заходом:

- **3.26** оказался настоящей гонкой, а не латентной: `Run` не дожидается
  фоновой задачи (проверено), так что `(sleep 0.1; echo late) &` пишет в
  буфер уже после того, как `exec` его прочитал. Под `-race`
  воспроизводится, с `SyncBuffer` — нет.
- **3.30** подтверждён обратной стороной: на машине разработки
  накопилось 963 каталога `/tmp/sennit-db-template-*`. Снимок теперь
  держится в памяти, а временный каталог удаляется сразу, включая пути
  с ошибкой.
- **3.27** исправлен не сообщением об ошибке, а по существу:
  tx-bound `Queries` выполняет чтение-запись в транзакции вызывающего,
  которая и даёт нужную атомарность.
- **3.13** и **3.24** — по описанию из разделов выше.

Отдельно: фикс **3.2** (фантомная строка в `read`) изменил вывод
инструмента для любого файла с завершающим `\n`, из-за чего кассеты
`TestCoderAgent/glm-5.1/{read_a_file,update_a_file,multiedit_tool}`
устарели. Перезаписаны в режиме `SENNIT_TEST_VCR_MODE=fixture` — он
пишет против локального `NewFixtureHTTPServer`, а не против платного
эндпоинта, так что живой доступ к модели не потребовался. Набор тестов
полностью зелёный.

Замечание на будущее: все 12 кассет всё ещё содержат прежнюю
формулировку описания `glob`, и это не мешает — `normalizeForMatch`
намеренно вычищает из сравнения прозу (системный промпт и описания
инструментов), оставляя строгими модель, параметры сэмплинга, имена и
схемы инструментов и все несистемные сообщения. Правка формулировки
кассеты не ломает; правка поведения — ломает, и должна.
