# Схлопывание тредов в делегации

Тред перестаёт быть отдельной сущностью и становится флагом изоляции на
делегации: `agent(subagent_type, isolation: "worktree")`. Восемь PR-ов, от
параметра тула до переезда собственной сессии в worktree.

- Ветка: `main`, дерево `d5da98ab1`
- Цель: 0.10
- PR с ломающими изменениями: 3 (PR 2, PR 3, PR 5)

Номера строк — по дереву `d5da98ab1`; перед началом каждого PR сверять.
Оценки объёма предварительные: PR 1, PR 3 и PR 7 требуют изменения
контрактов исполнения, сохранности работы и владения сессией.

## Зафиксированные решения

| | Решение | Почему |
|---|---|---|
| **merge** | Удалить автослияние и ручной merge API | Автоматически удалять worktree и ветку только при чистом дереве и подтверждённом отсутствии коммитов вне базы. Иначе сохранять обе. |
| **CLI** | `sennit threads` удалить в 0.10 | Ломающее изменение, без алиаса. Отметить в changelog. |
| **сессии** | Тегировать родительским проектом | Транскрипт изолированной делегации виден из родительской сессии. |
| **worktree-режим** | EnterWorktree в объёме | Собственная сессия переезжает в worktree и возвращается. |

## Что уже сделано за вас

Это причина, по которой план — на восемь PR-ов, а не на переписывание
подсистемы. Архитектура уже разделена по той же линии, по которой её режет
Клод.

- **`internal/toolmeta/toolmeta.go:129-133`** — управляющие тулы уже
  схлопнуты: `agent_list/result/cancel/send/output` держат `thread_*` и
  `task_*` как алиасы. Тред-специфичны остались ровно три.
- **`internal/thread/types.go:11-46`** — статусы разделены на **core** и
  **overlay** с комментарием «reachable only by a Thread». Оверлей помечен
  как оверлей самими авторами.
- **`internal/thread/types.go:89`** — `Delegation` + `Kind{task,thread}` в
  одной таблице. Клодовская модель — тот же объект с флагом вместо вида.
- **`internal/app/threadspawn/spawner.go:120`** — `LocalSpawner.Spawn`
  поднимает `app.App` **в процессе**, не отдельным процессом. Никакого IPC
  разбирать не придётся.
- **`internal/workspace/appws/threads.go:163`** — `AttachThread` уже отдаёт
  живой `workspace.Workspace` + release, а `internal/ui/model/root.go:68`
  уже умеет держать переднеплановый workspace на нём. Это каркас подключения
  UI, но не протокол переноса владения текущей сессией.
- **`internal/app/bootstrap.go:25`** — `BootstrapOptions` — готовый шов для
  `ProjectPath`-override: там уже живут `InheritedAgents`, `PreferredModel`,
  `ConfineWrites`.

## Последовательность PR-ов

Номера задают порядок реализации. PR 1 и 2 дают новую модель; PR 3
атомарно убирает merge вместе со всеми потребителями; PR 4 разделяет
рабочий корень и проект; PR 5 удаляет оставшийся CLI; PR 6 и 7 меняют UI
и владение сессией. PR 8 завершает пользовательскую документацию.

skills и описание несовместимости обновляются вместе с поведением,
а не откладываются до PR 8.

создавать агента по явным данным, сохраняя ограничения выбранного типа.

Отчёт доставляется родителю ровно один раз, карточка открывает нужную
сессию. Проверить смешанный параллельный запуск на общих лимитах, rollback
при сбое bootstrap и отмену во время подготовки.

`go build .`, `go test ./...`, `go test -race ./internal/thread`, `task lint`;
в платформенном CI проверить macOS/Windows-пути удаления worktree.

### PR 7 — EnterWorktree / ExitWorktree

Новый режим с передачей владения текущей сессией между app. Подключение
к чужой сессии не заменяет этот контракт.

*Зависимости: PR 4 (обязательно), PR 6. Ломающих изменений: нет.*

Разница с текущим поведением — не техническая, а смысловая. `AttachThread`
сегодня **открывает чужую сессию**, живущую в другом app. Клодовский
`EnterWorktree` **переносит вашу**: беседа та же, меняется корень. После
PR 4 обе сессии лежат под одним `project_path`, и «та же строка сессии в

**Ловушка.** `ConfineWrites: true` (`bootstrap.go:58`) поставлен тредам
намеренно: изоляция «не должна зависеть от промпта прав, который никто не
увидит». Для EnterWorktree человек *сам* сидит в этом воркспейсе и видит
промпты — но конфайн всё равно нужен, иначе «я в worktree» перестаёт
что-либо значить, стоит агенту написать по абсолютному пути в основное
дерево.

И `WorkspaceLock`: спавненные app берут блокировку канонического common dir
репозитория и работают параллельно с основным (`spawner.go:29`). Проверить,
что вход в worktree не порождает вторую сессию, конкурирующую за ту же
строку БД, с самим собой.

**Протокол владения, обязательный до реализации UI.**

1. Сериализовать enter/exit для session ID. Отказать в переключении при
   активном ходе или незавершённых инструментальных операциях, не обрывая их.
2. Подготовить целевой app и ресурсы без запуска сессии. До успешной
   передачи исходный app остаётся владельцем; ошибка подготовки делает rollback.
3. Передать право запуска ходов и маршрутизацию событий одному владельцу.
   Заблокировать запуск в прежнем app; переключить подписки UI только после
   успешной передачи. WorkspaceLock не заменяет блокировку session ID.
4. Сохранить доставку завершений уже запущенных делегаций: во время передачи
   они ожидают в inbox, затем обрабатываются ровно один раз текущим владельцем.
   Сами делегации не перезапускаются и не меняют рабочий корень.
5. Выход выполняет обратную передачу; закрытие app не удаляет беседу.
   Сохранять сведения о worktree и фазе перехода для восстановления после
   сбоя. При восстановлении не допускать двух владельцев и не удалять
   ресурсы, безопасность уборки которых не подтверждена.

**Проверка.** Вход, ход и выход сохраняют session ID и транскрипт;
повторный вход открывает тот же worktree. Проверить отказ при активном ходе,
одновременные enter/exit, сбой bootstrap, сбой на каждой фазе передачи,
перезапуск процесса, завершение делегации во время переключения и после
выхода, отсутствие дублей сообщений и параллельной записи двумя app.

## Открытые вопросы

Каждый блокирует конкретный PR. Ответы дешевле дать сейчас, чем обнаружить
их посреди PR 7.

### A (PR 7) — тулы для worktree или только команды человека?

У Клода `EnterWorktree`/`ExitWorktree` — тулы: модель сама решает уйти в
worktree и вернуться. Дать их модели значит дать ей менять корень посреди
хода.

**Рекомендация:** начать с команд человека (`/worktree`), тулы — отдельным
решением после того, как режим поживёт. Обратное сужение поверхности всегда
дороже расширения.

### B (PR 2) — что делать с агент-файлами, где в `tools:` написан `thread_create`?

Алиаса быть не может — заменяющего тула нет, есть параметр. Варианты: молча
выбросить имя; выбросить с предупреждением в `sennit doctor`; считать
ошибкой конфига.

**Рекомендация:** выбросить с предупреждением. Ошибка конфига ломает рабочие
проекты на ровном месте, а `doctor` у вас для этого и есть.

### C (PR 4) — мигрировать ли `project_path` у старых сессий тредов?

Постфактум родителя надёжно не определить: связь есть в
`threads.parent_session_id`, но только для строк, которые пережили все
прошлые миграции.

**Рекомендация:** не мигрировать. Новые строки пишутся правильно, старые
остаются под своим путём и через `sennit gc` уйдут сами. Одноразовая
аномалия в истории лучше, чем миграция, которая может переклеить чужие
сессии.

### D (PR 6) — как называется дашборд и пакет?

`delegations` точнее всего, но длинно для палитры и для `internal/ui/`.
`agents` занято смыслом «именованные агенты из `.sennit/agents`» и
перепутается.

**Рекомендация:** `delegations` — оно уже употребляется в этом значении по
всему коду и в `delegation.md`, так что расхождения имён не появится.
