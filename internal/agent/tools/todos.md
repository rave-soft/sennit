Manage a structured task list for multi-step work; each task has pending/in_progress/completed state. Every call REPLACES the whole list — always send the FULL list including completed tasks (marked completed, never dropped), so finished work stays visible; omit an item only to genuinely retract it. When working sequentially, keep one task in_progress at a time. When tasks run in parallel — delegated to threads or subagents — mark EVERY currently-running task in_progress and complete each one individually as its worker finishes, so the task list reflects real concurrent progress. Skip for simple or single-step tasks.
